AI Agent 气象科研实践基础

发表于2026-11-04|更新于2026-11-06|智能体应用
|总字数:5.4k|阅读时长:17分钟|浏览量:

现在可以用的 AI 智能体，或者说智能工作助手已经越来越丰富了，比如前面介绍过的 Claude code，还有 OpenAI 的Codex，腾讯的 workbuddy 等。他们安装和配置都很方便，能力上各有优势，可以彼此搭配起来用。后面就不再长文介绍安装和配置方法了，今天来简单梳理一下我学到的关于 AI Agent 的概念和关键应用。

AI Agent 基础应用

Agent 模式（自主编程+自动运行+闭环验证）

  • 能够在工作区内操作
  • 能够自主编写程序，不断试错，运行验证
  • 自动测试和交付任务结果，无需手工搬运

关键概念梳理

  • 命令行界面 （CLI）：在终端中输入命令与计算机交互的界面
  • 图形化用户界面 （GUI）：在系统桌面上使用图形化的窗口进行人机交互
  • 大语言模型 （LLM）：大语言模型主要预测下一个词语的概率分布
    • 大语言模型已经拥有足够的训练数据，智慧水平接近瓶颈，想要提升 LLM 的能力需要让 LLM 能够接触到工作区，配置好各类工具等 AI 基础设施
  • Tokenizer 编码：将原始文本编码为整数 ID 矩阵，并进行运算
    • 词元（token）：模型处理文本的最小单元，上下文、开销等通过 token 计量
    • 不要直接将大量的数据文件直接交给 Agent 处理，避免让模型直接参与数据的“心算”的任务，让模型通过编程来解决类似问题
  • 深度思考 （Reasoning）：模型不是直接通过一次前向传播输出答案，而是建立思考链，在回答问题过程中拆解问题、调用工具、尝试解答、自我对话反思和验证、自我纠错、动态调整策略等，提升解决复杂任务的准确性
  • 上下文 （context）：本次任务判断所需的信息集合，包含系统指令和项目说明，必要的对话历史，已读取的项目材料，工具返回结果（工具或编程程序的运行结果），当前用户新输入指令
  • 上下文窗口（context window）：工作台容量上限，决定单词会话最多容纳信息，包括历史记录和输入材料等，突破上限后继续运行，重要信息可能被忽略，时间开销会增加。通过独立开始新会话或压缩上下文等方式防止溢出
    • 单次输出上限：单次回复最多的内容，一般远小于上下文窗口
  • 项目级规划文件：CLAUDE.md 或 AGENTS.md 文件，适用于 AI Agent 的规则和说明文本，在项目或全局（所有项目）中规范和约束 Agent 的行为，
  • 跨会话项目交接： Agent 有上下文窗口限制，一般需要通过开启新会话来继续执行任务，但新会话上下文清空，这时需要文档来保存任务执行关键信息。
    • Andrej Karpathy 提出的大模型项目知识库（LLM-wiki） 与任务进程（PROGRESS.md），让模型能够在关闭窗口前自动更新项目知识库和交接日志，保存在硬盘上，当创建新的会话后，能够快速学习项目内容和进程并继续推进新的任务
  • 检索增强生成 （RAG）：长文档的精准匹配机制，避免文档全文遍历，而是制作全文目录索引的方式，让模型精准匹配信息，并放入到 context，模型根据节选信息回答，节省 context window 占用、token和时间的开销
  • 提示词 （prompt）：结构化指令包含背景依据、具体任务、交付规范
    • 前台用户提示词：你在对话框中直接告诉模型的信息
    • 后台系统提示词：预设提示词，例如定义模型的身份，每一个新会话启动都会自动输入
  • 工具 （tool）：包含运行框架（Harness）和工具函数（tool function），让模型能够动手操作
    • 完整执行链路：框架自动挂载自带的工具+模型输出调用请求+平台执行工具函数+结果返回模型
    • tool 一般由模型自主选择使用，当用户提问后，工具的定义会自动输入给 LLM，用户无需手动详细指定
  • 模型上下文协议（MCP）：连接 Agent 与外部平台的接口，让模型能够通过该接口调用外部服务，完成当前任务
    • 提示：MCP 可以提高模型能力和效率，但开启过多的 MCP 服务反而影响质量，占用上下文窗口，因此 MCP 服务和其他工具需要按需挂载，避免功能重叠干扰或者误触发
  • 技能 （skill）：模块化的 prompt，以 SKILL.md 为核心入口，保存特定任务的执行步骤、核验标准和配套资源，相当于为 Agents 提供了专业技能书，在通用能力基础上增加了专有的能力
    • skill 不一定要自己写，可以从网络上获取，也可以让 Agents 根据当前工作方式制作一份 skill
    • 将常用的工作或流程总结为一个 skill 可以不让 AI 再次探索同一个任务的完成方法，也不用每一次在项目规划文件中再次声明，显著减少 token 和时间的开销
  • 定时任务触发器：在日常办公中常用，在固定时间触发特定任务，办公类 Agent，例如腾讯workbuddy ，可以很方便的设置定时任务，比较常用

AI Agent 的规范使用提示

核心步骤

  1. 任务说明
  2. 读取文件
  3. 制定步骤
  4. 执行工具
  5. 核验结果

建立高性价比的模型工作流

  1. 顶层规划与追问：在任务开始执行前，模型根据任务说明，使用只读的 Plan 模式，用高推理强度的模型（例如DeepSeek V4 Pro）了解任务和项目大致情况，之后向用户发问（可以使用 grill-me），确定关键细节，制定严密计划，澄清边界
  2. 代码编写与工具执行：用轻量级模型（例如DeepSeek V4 Flash）执行代码改写和测试
  3. 最终把关检查与验收：用高推理强度的模型进行回顾和把关，可以使用其他的旗舰模型进行交叉检验，并交付验收结果

将项目任务结构化

应用软件开发项目的习惯，一个复杂的任务分为多个模块，建议使用 git 进行版本管理，例如一个 Python 语言为基础的项目可以这样组织

这里提供一个大致思路，实际组织方式需要根据你的项目实际情况而定

5 步骤的模型验收清单

任务完成后让模型返回，最好写入日志

  1. 用户的需求，重复一遍
  2. 关键的工具执行记录
  3. 输出文件与修改摘要
  4. 实际验证和测试结果，声明参与验证的数据边界
  5. 尚未完成或尚未验证的项目

所有结果必须有可追溯的来源，必须有数据和日志的支持

Agent 工作组织方式的自由组合

  1. 单Agent VS 多 Agent协作
  2. 固定工作流 VS 模型动态自主决策
  3. 边想边干 VS 规划再执行

选Agent 的考虑要点

目前主流的 Agent 在以下方面基本都表现的不错，但也有差异需要用户权衡

  1. 工具调用成功率：模型会通过输出结构化数据来实现工具调用。是否会出现错误调用工具或调用不存在的工具
  2. 任务一次通过率：模型编程后，进行测试，能否一次就成功
  3. 材料类型与长文抗噪：当模型阅读了大量的文档、代码、日志后能否精确定位关键信息和问题
  4. 端到端完成时间：一次任务，Agent 会反复调用模型API，单次首字延迟（TTFT）和吐字速度（TPS）直接决定任务总时长
  5. 单次任务成本：跑通整个任务的账单
  6. 部署与合规条件，是否包含保密信息，保密信息不要连接公网 API，在内网单独部署模型

复杂任务的智能体团队协作

  • 主从派发：设计子智能体（sub agent），每个智能体有独特的 Harness 和 context window
    • 对话中自动主动派发，分工协作，例如 Codex，在大的项目代码中，每个 Agent 分别检查和修改特定的模块，彼此相互通讯和协作
    • 很多简单的任务单个智能体就可以完成，多智能体 token 开销会增大
  • 角色分工：手动定制不同领域的专家智能体，每个智能体有各自的专长
    • 例如 workbuddy 或 OpenClaw，可以为每个智能体绑定专属提示词和工具，创建不同角色，例如科学计算编程专家、文献调研专家、项目审查者、前端开发专家、后端开发专家等

大文件处理思路

例如 Excel 表文件，或者其他很长但具有规律的文件

  1. 不要让模型直接参与处理大量数据，这不仅浪费 token，还很容易出错
  2. 可以让模型只看“表头或前几行案例和记录”
  3. 让模型编写程序或使用本地确定性的自动化程序（如 Python 脚本等）处理全部数据
  4. 只把程序运行最终结果返回上下文，而不是把全部数据填充到上下文

持续工作与无人值守

  1. 大型课题断点续传：在项目空间内，每次 Agent 收工前将已确认分支和待办写入 PROGRESS.md ，次日新开任务直接读取该文件，恢复上下文并继续任务
  2. 本地脚本定时运行：始终在本机上运行，本机关机或 Agent 客户端界面关闭则不会运行
  3. 云端服务汇总：Github 仓库、在线文档等云端信息的定时抓取、汇总、整理，并制作报告，或通过邮件、飞书等方式发送给用户

通用与专用Agent

  1. 通用/多用途：资料整理，数据分析，编程与文件处理等
  2. 专用/垂直 Agent，例如气象观测数据质控，气象预报检验等 Agent，可以自己设计和创建。例如，字节跳动 Coze 平台是目前国内常用的智能体开发平台，可以在该平台创建自己需要的 Agent

常见的通用 Agent：Claude code，Codex，workbuddy，OpenClaw 等，可以根据需要自由配置 LLM

AI Agent入门实战案例

示例一：高质量检索和精读论文

Agent 可以高效检索论文，节省科研时间

思路：什么主题？什么时候发布？来源是否可靠？

项目目录结构

  • papers/：5 篇原始 PDF。
  • 文献总结Word/：5 份逐篇双语结构化报告和 1 份综合进展报告。
  • references.csv：题名、作者、年份、期刊、DOI、链接、页数和 SHA-256。
  • search_log.md：检索策略、候选筛选、排除原因和不确定性。
  • PROMPT.md：可直接布置给 Agent 的专业提示词。
  • qa_report.md：最终验收证据。
  • source_research/：全文抽取文本、逐篇证据笔记和原始研究清单，供复核。
  • src/build_word_reports.py：从已核验笔记重新生成 Word 的脚本。

以下为PROMPT.md 提示词：供Agent直接阅读，这里提供一个示例，你可以直接抄作业，也可以根据自己的实际情况进行修改。例如文中使用多 Agents 并进行了分工。如果你不具备多 Agents 运行的条件，你可以删除分工过程的提示词

输入：数据源（在哪里下载？），请求规格（何时起报？空间范围？物理量？），物理量预处理规范（单位转换？），交付方式（原始数据？图片？）
